# Apiserver compatibility modes

Soapbox can project the RBAC authorizer with either the real
`k8s.io/apiserver` API or a deliberately smaller module-local API. The selected
mode is part of the profile hash because it changes public type identity,
function signatures, dependencies, provenance, and generated bytes.

The published `monis.app/kk/rbac_authorizer@v0.36.1` remains an **external**
artifact and is immutable. The current `soapbox.yaml` selects **local** for the
next eligible Kubernetes release. Reconciliation therefore starts a new
profile epoch from the existing destination `main`; it does not regenerate or
move `v0.36.1`.

## `external`

`compatibility.apiserver: external` preserves upstream compatibility:

- `user.Info`, authorization attributes and decisions, authorizer interfaces,
  and rule-info interfaces retain their real `k8s.io/apiserver` identities;
- `ConfirmNoEscalation` continues to read the user and namespace from the real
  private apiserver request context;
- generated assertions prove `RBACAuthorizer` implements the real apiserver
  `Authorizer` and `RuleResolver` interfaces; and
- `k8s.io/apiserver` remains in `go.mod` and the loaded module graph.

The component-helper copy is independent of this choice. Even in external mode,
`k8s.io/component-helpers/auth/rbac/validation` is copied under `internal/kk`,
and the external module is forbidden from imports, requirements, checksums, and
the loaded graph.

## `local`

`compatibility.apiserver: local` intentionally does **not** preserve apiserver
type identity. Soapbox generates the exact surface retained RBAC code needs:

- `UserInfo` and `DefaultUserInfo`;
- `Attributes` and `AttributesRecord`;
- `Decision` and the deny, allow, and no-opinion constants;
- `Authorizer` and `RuleResolver`;
- resource and non-resource rule-info interfaces and default records;
- `SystemPrivilegedGroup`; and
- the allocation-free service-account username comparison used by subject
  matching.

Retained imports are rewritten to those generated packages. External interface
assertions become local assertions, and the generated facade exports the local
types directly. `ConfirmNoEscalation` receives explicit `UserInfo` and namespace
arguments instead of attempting to reproduce apiserver's private context keys.
The incompatible internal-version adapter is pruned.

These are intentional API and behavior changes. The generated `NOTICE`, report,
and per-file modification notices disclose them. Both
`k8s.io/apiserver` and `k8s.io/component-helpers` are forbidden in local mode.
The dependency gate checks five independent surfaces: raw imports, parsed
`go.mod`, parsed `go.sum`, `go list -m all`, and typed package-module identities.

## v1.36.1 control-pair certification

Both modes were generated twice from Kubernetes commit
`756939600b9a7180fc2df6550a4585b638875e67` using the Soapbox 0.2.0 candidate
and the same staging index. Each mode reproduced byte-identical trees and JSON reports on its second
run. The manifests remained mode-specific and stable.

The local zip is larger because it owns three compatibility packages, while its
resolved module and package graphs are substantially smaller. Cache timings are
observational measurements from one run, not deterministic publication inputs.
The canonical zips were rendered with `golang.org/x/mod/zip` as
`monis.app/kk/rbac_authorizer@v0.36.1` solely to compare the two control trees.

Both trees passed `go test`, `go test -race`, `go vet`, and `go build`. The local
tree contained neither forbidden module on any required surface; the external
tree contained component-helpers on none and retained the exact apiserver
requirement and interface identity.

The checked-in release-certification templates are:

- `tools/internal/generate/testdata/external_apiserver_behavior_test.go`; and
- `tools/internal/generate/testdata/local_apiserver_behavior_test.go`.

Copied into the corresponding generated module root, they exercise the same
resource authorization and denial, rule resolution, subject location,
service-account matching, and no-escalation decisions. The external test uses
real apiserver attributes and request-context helpers. The local test uses only
the generated facade and passes explicit user and namespace inputs. Both passed
against the v1.36.1 control pair.
